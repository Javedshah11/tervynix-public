Security is important to Tervynix.

Tervynix is currently under active development, and its security processes will continue to evolve as the platform grows.

## Reporting a Security Vulnerability

Please do not publicly disclose security vulnerabilities through GitHub Issues, Discussions, social media, or other public channels.

If you discover a potential security issue, report it privately.

A dedicated security contact method will be added as the project infrastructure matures.

Until then, please avoid publishing:

- Authentication vulnerabilities
- Authorization bypasses
- Remote code execution issues
- Sensitive data exposure
- Credential leaks
- Session or token vulnerabilities
- Infrastructure vulnerabilities
- Dependency-related security issues
- Privilege escalation issues

## What to Include

When reporting a vulnerability, include:

- A clear description of the issue
- Affected component
- Steps to reproduce
- Expected behavior
- Actual behavior
- Potential impact
- Screenshots or logs when useful
- Suggested mitigation, if known

Do not include unnecessary personal data or credentials.

## Sensitive Information

Never submit real:

- Passwords
- API keys
- Access tokens
- Private keys
- Database credentials
- Production secrets
- `.env` files
- User data

Use redacted or example values when demonstrating an issue.

## Supported Versions

Tervynix is currently in active development.

Security support information for production releases will be published when stable versions become publicly available.

## Responsible Disclosure

Please allow reasonable time for investigation and remediation before publicly discussing a vulnerability.

Responsible security research is appreciated.
