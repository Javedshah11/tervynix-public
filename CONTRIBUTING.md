# Contributing to Tervynix

Thank you for your interest in Tervynix.

Tervynix is currently under active development. This public repository is used for product documentation, roadmap discussion, feature ideas, community feedback, and public project updates.

The main application source code may be maintained separately.

## Ways to Contribute

You can help Tervynix by:

- Reporting bugs
- Suggesting features
- Improving documentation
- Sharing technical feedback
- Testing future releases
- Reviewing product ideas
- Participating in discussions
- Helping improve developer workflows

## Reporting Bugs

When reporting a bug, please include:

- A clear description of the problem
- Steps to reproduce it
- What you expected to happen
- What actually happened
- Operating system
- Browser, if applicable
- Screenshots or recordings when useful

Avoid including passwords, tokens, API keys, private source code, or other sensitive information.

## Feature Requests

Feature suggestions are welcome.

A useful feature request should explain:

1. The problem
2. The proposed solution
3. Why it would help developers
4. Any alternatives you considered

Please focus on the problem rather than only describing a specific UI implementation.

## Documentation Contributions

Documentation improvements are welcome, including:

- Fixing unclear explanations
- Correcting mistakes
- Improving examples
- Improving architecture documentation
- Adding useful developer guides

## Discussions

Use GitHub Discussions for:

- Product ideas
- Questions
- Architecture conversations
- Feedback
- Developer workflow suggestions
- General Tervynix discussion

Use GitHub Issues for specific bugs or actionable feature requests.

## Development Contributions

As Tervynix evolves, selected components or repositories may become available for direct code contributions.

Contribution instructions for those components will be published when appropriate.

## Code of Conduct

Be professional and constructive.

When participating in the Tervynix community:

- Respect other contributors
- Discuss technical disagreements constructively
- Avoid harassment or personal attacks
- Keep discussions relevant
- Provide useful context when reporting problems

## Security Issues

Do not publicly disclose security vulnerabilities.

Security reporting instructions will be maintained separately in `SECURITY.md`.

## Project Direction

Before proposing major architectural changes, review:

- `README.md`
- `ROADMAP.md`
- `VISION.md`

This helps keep contributions aligned with the direction of Tervynix.

---

Thank you for helping improve Tervynix.
